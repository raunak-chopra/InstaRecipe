# Search, screenshot import and recipe comments — 27 October 2026

## Requested behavior

The owner reported search failing on a real device and requested screenshot recipe import, automatic recipe extraction from Reel comments, and removal of AI/decorative images while keeping personal cook photos. Existing colours, the personal Gemini-key model, dependency versions and Room schema stay unchanged. The owner will test on a physical device; no emulator work is authorized for this change.

## Implementation

- **Search:** the library previously depended entirely on asynchronous FTS IDs. A stale/empty/failing index could hide content that was already loaded. The exact failing device index was not captured, so this is a diagnosed dependency/coverage gap, not a proven device-specific database corruption claim. Search now matches the actual loaded saved recipes immediately, across title, creator, category, tags, ingredients, steps and notes. Multiple terms must all match; case, punctuation and accents are normalized. Existing category/favorite/cooked/tag filters remain combined with the query. No database rebuild or migration is needed.
- **Screenshot:** Add recipe → Import recipe screenshot, Android image Share → InstaRecipe, or Read recipe screenshot within an existing draft's recovery tools. The selected content URI is bounded to 10 MB, checked as PNG/JPEG/WebP, dimension-checked and sampled before JPEG encoding. The request uses inline image data through the existing Gemini client and primary/backup-key behavior. It asks for legible text only, preserves partial results and opens review; it does not generate recipe photos or infer ingredients from a food picture. The original image stays on the device; no new stored recipe-photo field is used. Missing key/read/request errors explain recovery. A failed request can be retried by choosing the source again; the app does not promise to retain a screenshot attachment after process death.
- **Comments:** Reel import automatically inspects recipe comments returned by the existing authenticated media response or a bounded public-page lookup. Public embedded comment data is accepted only for the matching Reel shortcode. Creator comments take precedence over conflicting community suggestions; community-only content is explicitly labelled unverified. Up to five distinct recipe-like comments are included, with author/source attribution retained in notes. Source text is treated as untrusted data in the extraction prompt.
- **Comment limits:** this is best-effort retrieval of comments Instagram exposes in accessible media/page metadata. It does not unlock restricted comments, promise complete/paginated comment access, or add a Meta professional-account token/service. If Instagram omits/blocks the data, the existing video/caption path continues and screenshot/pasted-text recovery is available. Live Instagram/Gemini behavior still needs the owner's real-device check; tests use local fixtures and MockWebServer only.
- **Photos:** nine generated decorative assets were moved from packaged `drawable-nodpi` resources into `docs/retired-decorative-assets-2026-10-27/`, retaining original source files for review/rollback. Legacy chapter metadata no longer references those resources. Personal CookPhoto storage, fields, rendering and actions are unchanged. No user photo or recipe data was deleted.

Google documents image input as inline base64 or uploaded media; this uses the existing generateContent transport rather than adding an SDK/dependency: [Google image understanding](https://ai.google.dev/gemini-api/docs/image-understanding). Meta's comment documentation was requested during investigation but returned HTTP 429; no new universal personal-account API capability is assumed.
